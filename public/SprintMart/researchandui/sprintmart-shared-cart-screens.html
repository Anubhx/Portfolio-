Shared Cart — All Screens

Every screen and UI state for the SprintMart Shared Cart feature, built to the locked design system in colours.md and the screen list in screens.md, at native iPhone size (393×852). Static high-fidelity HTML/CSS only — no scripts, no simulated navigation. Frames are laid out side by side, grouped by flow section, ready to pull into Figma with html.to.design.

Deep Plum — structure Slate — neutral Amber — action / on-track Orange — emphasis / warning Burgundy — urgency / over-cap new reused state component

0 · Home / Products

reused base screen

Unchanged from the base SprintMart app per screens.md — the only addition is the household banner layered on top (Jakob's Law: nothing else about Home should feel new).

1.1 · Create Shared Cart

3 states

Two payment modes exist because flatmate money dynamics differ fundamentally from family ones — a single mode would over- or under-serve one group. Traces to both personas' need for an agreed-upfront contract.

1.2 · Invite Members

3 states

Joining must take under 30 seconds for the Contributor persona (Rohan) — no separate sign-up step for existing SprintMart users.

1.3 · Join Shared Cart

3 states

What a Contributor sees when they tap the invite link. Showing the cap upfront is the contract-agreed-before-shopping principle.

2.1 · Shared Cart Dashboard

4 states

The home base of the whole feature. Three-tier item list is the 'visibility without surveillance' mechanism: everyone can see, only the owner (or admin) can touch — greyed controls on others' items are the actual UI expression of that rule. Budget bars chunk four people's numbers into one glanceable unit each (Miller's Law).

2.2 · Activity Timeline

2 states

Directly answers the recurring pain point “nobody knows who removed an item.” Chronological, read-only, ambient — ties into the ownership rules shown on the Dashboard.

3.1 · Search & Duplicate Nudge

4 states

Search, browse and add stay pixel-identical to the base single-user app (Jakob's Law) — the only new layer is the duplicate nudge. Hick's Law in practice: exactly two choices, one inline banner, never a modal, so the under-30-second Contributor never has to think twice.

3.2 · Shared-Item Nudge

1 state

Every item defaults Personal. A soft, dismissible prompt catches obviously-household products (cooking oil, detergent) so contributors don't have to remember to toggle every time — matching the instinct people already have offline.

4.1 · Budget Cap Approval

2 states

A hard block would be a dead end with no recourse. Request-and-approve respects the contributor's autonomy while keeping the admin in control — mirroring how households actually negotiate.

4.2 · Edit Budget Cap

1 state

Explicit, per-person control rather than automatic reallocation — redistributing unused cap would create perverse incentives to spend less so others can spend more.

5.1 · Checkout Review

2 states

The admin's last look before locking — the explicit, visible conflict-resolution moment for shared-item classification, resolved before payment rather than during or after.

5.2 · Cart Locked

1 state · transition

Brief by design (screens.md marks this a transition state, not a full screen) — confirms to everyone the cart is frozen and the payment clock has started.

5.3 · Bill Split / Payment

4 states

10 minutes echoes SprintMart's own delivery promise — long enough to open the app, short enough to feel like a real deadline. Nobody fronts anything: each payment is personal and direct, not collective and asymmetric.

5.4 · Admin Pays Checkout

1 state

The simpler path when Admin Pays was selected at creation — reuses the base app's cost-summary checkout pattern; no multi-payer window needed.

6.1 · Order Confirmed

1 state

Closes the social loop — the admin-covers fallback stays neutral Slate, never Burgundy, so Kabir's missed window never reads as a public callout.

6.2 · Live Order Tracking

2 states

Unchanged from the base app, per screens.md — shared with all members, not just whoever placed the order.

7.1 · Shared Cart Settings

1 state

One simple list for the permission controls the user stories call for — payment mode, per-member caps, and permissions all in one place, not buried across screens.
