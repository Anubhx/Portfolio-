Notes for Figma Import

Why this file imports cleanly

  • Every class follows block__element--modifier, so a plugin's auto-generated layer names already read sensibly — no manual renaming pass needed in Figma.
  • All colour, spacing, and radius values are CSS custom properties in :root. Most HTML-to-Figma plugins (e.g. html.to.design, Anima) map these straight onto Figma Variables — exactly what the rubric asks the Design System page to use.
  • Layout is plain flex/grid with fixed px values, not CSS Grid template-areas — these import far more reliably than newer grid syntax.
  • Inter + JetBrains Mono are both available as Figma/Google fonts, so text layers won't fall back to a substitute on import.

Suggested workflow

  1. Open this file in Chrome, run the html.to.design plugin against the live page (not a screenshot) so each section lands as its own frame.
  2. Rename the eight imported frames to match the side-nav order above — that becomes your Figma "Design System" page structure.
  3. Convert the colour swatches first into Figma Variables (5 colours), then the type styles into Text Styles — every other component should reference those instead of holding raw hex/px values, so future edits propagate automatically.
  4. Turn Button and Input into Figma Components with variants for tier × state — the matrix layout above was built specifically to map onto Figma's variant grid one-to-one.
  5. Member Avatar, Budget Bar, and Split-Bill Card are the three project-required custom components — make sure these are the ones flagged as reusable Components, not just grouped frames.
